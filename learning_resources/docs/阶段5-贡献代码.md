# 阶段5: 贡献代码

## 1. 准备工作

### 1.1 Fork和克隆

```bash
# 1. 在GitHub上fork pytorch/pytorch

# 2. 克隆你的fork
git clone https://github.com/YOUR_USERNAME/pytorch.git
cd pytorch

# 3. 添加upstream remote
git remote add upstream https://github.com/pytorch/pytorch.git

# 4. 初始化子模块
git submodule update --init --recursive
```

### 1.2 创建开发分支

```bash
# 更新main分支
git checkout main
git pull upstream main

# 创建feature分支
git checkout -b fix/issue-12345
```

## 2. 寻找合适的Issue

### 2.1 Good First Issue

访问: https://github.com/pytorch/pytorch/issues?q=is:open+label:"good+first+issue"

**特点**:
- 标记为"good first issue"
- 代码改动相对较小
- 有明确的问题描述

**示例类型**:
1. 文档修复
2. 简单bug修复
3. 添加类型标注
4. 改进错误消息

### 2.2 评估Issue难度

**容易** (1-2天):
- 修改错误消息
- 添加类型提示
- 简单的参数检查

**中等** (3-5天):
- 修复特定场景的bug
- 添加新的参数选项
- 改进现有功能

**困难** (1-2周):
- 实现新算子
- 性能优化
- 架构改进

## 3. 修复Bug的流程

### 3.1 复现问题

```python
# 根据issue描述创建最小复现代码
import torch

def test_bug():
    x = torch.tensor([1, 2, 3])
    # ... 触发bug的操作
    y = x.some_operation()
    print(y)

test_bug()  # 确认能复现
```

### 3.2 定位代码

**使用工具查找**:
```bash
# 查找相关函数
./learning_resources/tools/explore_pytorch.sh find-func some_operation

# 查找算子
./learning_resources/tools/explore_pytorch.sh find-op some_op
```

**设置断点**:
```python
import pdb; pdb.set_trace()
```

### 3.3 修复并测试

```bash
# 修改代码后
cd build
ninja torch_cpu  # 增量编译

# 验证修复
python test_bug.py

# 运行相关测试
python test/test_torch.py TestTorch.test_some_operation
```

## 4. 添加测试

### 4.1 单元测试

**位置**: `test/test_*.py`

```python
# test/test_torch.py
class TestTorch(TestCase):
    def test_my_fix(self):
        # 测试正常情况
        x = torch.tensor([1, 2, 3])
        y = x.some_operation()
        self.assertEqual(y, expected_output)

        # 测试边界情况
        x_empty = torch.tensor([])
        self.assertRaises(RuntimeError, lambda: x_empty.some_operation())

        # 测试不同设备
        if torch.cuda.is_available():
            x_cuda = x.cuda()
            y_cuda = x_cuda.some_operation()
            self.assertEqual(y_cuda.cpu(), expected_output)
```

### 4.2 Doctest

## 5. 代码风格

### 5.1 Python代码

**常见规范**:
- 使用4空格缩进
- 行长度 ≤ 120
- 使用类型标注

### 5.2 C++代码

**常见规范**:
- 使用2空格缩进
- 命名: `snake_case` (函数) + `CamelCase` (类)
- 使用 `auto` 简化类型

### 5.3 使用lintrunner

PyTorch使用lintrunner统一管理代码风格检查：

```bash
# 运行lint并自动修复
lintrunner -a

# 仅检查不修复
lintrunner
```

> **注意**: 不要使用 `make lint` 或直接运行 `flake8`/`mypy`，lintrunner会处理所有检查。

## 6. 提交PR

### 6.1 Commit消息格式

```bash
git add <修改的文件>

git commit -m "Fix issue #12345: brief description

Detailed explanation of what was changed and why.

Test Plan:
- Tested scenario A
- Tested scenario B

Fixes #12345
"
```

**格式要求**:
- 第一行: 简短描述 (≤50字符)
- 空一行
- 详细说明修改内容
- 说明测试方法
- 引用相关issue

### 6.2 推送到GitHub

```bash
git push origin fix/issue-12345
```

### 6.3 创建Pull Request

1. 访问你的fork: `https://github.com/YOUR_USERNAME/pytorch`
2. 点击"Pull Request"
3. 填写PR描述:

```markdown
## Summary
简要说明这个PR做了什么

## Test Plan
如何测试这个修改:
- [ ] Tested on CPU
- [ ] Tested on CUDA
- [ ] Added unit tests

## Related Issues
Fixes #12345
```

## 7. Code Review

### 7.1 响应Review意见

**Reviewer可能要求**:
- 添加更多测试
- 修改代码风格
- 优化性能
- 补充文档

**如何响应**:
```bash
# 根据意见修改代码
# ...

# Commit修改
git add .
git commit -m "Address review comments

- Added more test cases
- Improved error handling
"

# 推送更新
git push origin fix/issue-12345
```

### 7.2 保持PR更新

```bash
# 定期同步upstream
git checkout main
git pull upstream main
git checkout fix/issue-12345
git rebase main

# 解决冲突(如果有)
# 推送更新(需要force push)
git push origin fix/issue-12345 --force
```

## 8. CI/CD检查

### 8.1 理解CI流程

PR提交后会触发CI:
1. Lint检查
2. 类型检查
3. 单元测试 (Linux/Windows/Mac)
4. 文档构建

### 8.2 查看CI结果

在PR页面查看:
- 绿色✓: 通过
- 红色✗: 失败

**如果失败**:
1. 点击"Details"查看日志
2. 定位错误原因
3. 本地修复并推送

### 8.3 常见CI失败

**Lint失败**:
```bash
# 本地运行
make lint
```

**测试失败**:
```bash
# 本地运行相同测试
python test/test_torch.py TestTorch.test_some_operation -v
```

**类型检查失败**:
```bash
# 运行mypy
mypy --config mypy.ini torch/some_file.py
```


1. 寻找下一个issue

## 10. 高级话题

### 10.1 成为Reviewer

**要求**:
- 至少贡献过5个PR
- 对某个模块有深入理解
- 活跃参与社区

**职责**:
- Review其他人的PR
- 提供建设性意见
- 帮助维护代码质量

### 10.2 参与设计讨论

**RFC流程**:
1. 在 https://github.com/pytorch/rfcs 提交RFC
2. 社区讨论
3. 达成共识后实现

### 10.3 维护模块

成为某个模块的maintainer:
- 负责该模块的设计和开发
- Review相关PR
- 参与roadmap规划
